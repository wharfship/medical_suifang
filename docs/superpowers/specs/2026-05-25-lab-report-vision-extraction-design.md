# 化验单视觉提取演示设计

**目标**

新增一个独立的 Gradio 演示页，支持上传 `.docx` 或图片化验单文件，使用视觉模型提取首位患者的化验项目，并导出包含 `项目名称`、`结果`、`单位` 三列的 `xlsx` 文件。

**范围**

- 第一版只做独立演示，不改现有随访主页面。
- 输入只支持 `.docx`、`.png`、`.jpg`、`.jpeg`。
- `.docx` 默认只处理文档中的第一张嵌入图片。
- 若文件里可能包含多位患者，只保留第一张中第一位患者的结果。
- 输出固定三列，不包含参考范围、异常标记等扩展字段。

**架构**

新增一个轻量提取模块，负责：

1. 校验输入文件类型。
2. 将图片文件直接转为 Base64 Data URL。
3. 从 `.docx` 中提取第一张嵌入图片，再转为 Base64 Data URL。
4. 调用 DashScope OpenAI 兼容视觉接口，请模型仅返回结构化 JSON。
5. 对模型结果做最小清洗：列名归一、去空、去重、保序。
6. 将结果导出为 `xlsx` 并返回给演示页。

新增一个独立 Gradio 页面，只承担文件上传、触发提取、展示结果、下载 `xlsx` 四件事。

**模型策略**

- 视觉模型沿用现有项目的 `DASHSCOPE_API_KEY` 与 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
- 默认使用 OCR 向模型 `qwen-vl-ocr-latest`。
- 提示词强约束输出为 JSON：
  - 只提取第一位患者。
  - 只返回 `items` 数组。
  - 每一项只包含 `项目名称`、`结果`、`单位`。
  - 无法识别的字段留空，不补造内容。

**文件边界**

- `lab_report_extractor.py`
  - 文件输入处理
  - `.docx` 图片提取
  - 视觉模型调用
  - 结果清洗
  - `xlsx` 导出
- `extract_demo.py`
  - 独立 Gradio 演示页面
- `tests/test_lab_report_extractor.py`
  - 清洗逻辑与导出逻辑的最小测试

**错误处理**

- 文件类型不支持：返回明确错误。
- `.docx` 中没有图片：返回明确错误。
- 未配置 `DASHSCOPE_API_KEY`：返回与现有项目一致的配置错误。
- 模型返回非 JSON 或未提取到有效项目：返回明确错误，不导出空表。

**验证策略**

- 先用测试锁定清洗与导出行为。
- 再实现最小业务代码。
- 最后运行针对性测试，并验证独立演示页可以正常启动。
