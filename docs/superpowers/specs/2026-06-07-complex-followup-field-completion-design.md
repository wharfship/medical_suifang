# 复杂随访字段完成判定设计

## 背景

当前项目中，以下 5 个复杂字段虽然属于多子项问题，但在 `field_rules.py` 中仍会落入宽松的文本收口逻辑：

1. `（若有高血压）药物控制方案`
2. `（若有糖尿病）药物控制方案`
3. `（若曾患冠心病）治疗方式`
4. `（若曾患脑血管病）具体疾病、治疗方式及有无后遗症`
5. `（若有其余病史）请描述具体疾病、治疗方式、用药种类、用法、治疗效果`

现状问题：

- 只要患者回答像一段“具体文本”，系统就可能直接判定 `done + complete`。
- 这与 `2026.2.2人工智能供者随访计划excel版补充.xls` 第四列“填写内容规则”的要求不一致。
- 如果直接改成“缺项就一直追问”，又会出现两个问题：
  - 患者某一项明确不知道，但系统仍重复问同一项。
  - 患者某一项说不知道后，系统把本字段其他仍应继续收集的信息一起跳过。

本设计只修改 `field_rules.py`，不引入新的 Excel 驱动逻辑。

## 目标

- 让上述 5 个复杂字段的完成判定严格参考 Excel 第四列要求。
- 不再允许这 5 个字段被“宽松文本规则”直接收口。
- 让系统按槽位有逻辑地追问：
  - 某个槽位明确不知道后，不再重复追问该槽位。
  - 同字段其他未完成槽位仍继续追问。

## 范围

本次只处理以下 5 个复杂字段：

1. `（若有高血压）药物控制方案`
2. `（若有糖尿病）药物控制方案`
3. `（若曾患冠心病）治疗方式`
4. `（若曾患脑血管病）具体疾病、治疗方式及有无后遗症`
5. `（若有其余病史）请描述具体疾病、治疗方式、用药种类、用法、治疗效果`

以下字段不属于本次复杂字段严格化目标：

- `其余病史及用药情况`
- `尿常规：尿蛋白、尿潜血`
- `肾脏彩超`

## 总体设计

### 1. 区分普通文本字段与严格复杂字段

- 保留现有普通文本字段的宽松收口策略。
- 对上述 5 个字段新增单独的“严格复杂字段”判定逻辑。
- 这 5 个字段不再以“文本是否足够具体”作为 `done` 条件。

### 2. 用槽位驱动复杂字段判定

每个复杂字段拆成若干必填槽位。

每个槽位有以下终态：

- `answered`：该槽位已得到可记录答案。
- `unknown`：患者明确表示不知道、记不清、不清楚。
- `not_applicable`：该槽位因分支未触发而不适用。

还有一个非终态：

- `missing`：该槽位仍需继续追问。

### 3. 新的字段完成定义

对复杂字段：

- `done`：该字段下所有“已触发的必填槽位”都进入终态。
- `ask_again`：仍至少存在一个 `missing` 槽位。

这里的关键点：

- `done` 不等于“所有槽位都答出来了”。
- `done` 的含义是：该问的都问过了，知道的记下，不知道的也明确落定。

### 4. 分支触发逻辑

复杂字段的部分槽位属于条件分支，必须根据患者实际回答来触发。

规则如下：

- 如果患者提到“有药物/吃药/口服药”，则触发药物分支。
- 如果患者提到“有胰岛素”，则触发胰岛素分支。
- 如果患者提到“做过手术”，则触发手术分支。
- 如果患者明确表示“未用药/未打胰岛素/未手术”，对应分支记为 `not_applicable`，不再继续追问该分支内部槽位。

### 5. 槽位追问逻辑

- 同一轮只围绕当前最关键的缺失槽位追问。
- 如果某槽位被明确回答为“不知道/记不清/不清楚”，该槽位转为 `unknown`，后续不再反复追问同一槽位。
- 不因为单个槽位是 `unknown`，就结束整个字段。
- 必须继续追问本字段中其他仍为 `missing` 的槽位。

## 五个复杂字段的 `done` 规则

以下规则严格参考 Excel 第四列“填写内容规则”，并加上分支逻辑。

### 1. `（若有高血压）药物控制方案`

Excel 规则：

- 药物名称
- 规格
- 一天几次
- 一次几片（粒）
- 血压控制水平

判定规则：

- 必须先明确是否在用药控制高血压。
- 如果回答中触发“用药”分支，则以下槽位全部为必填：
  - 药物名称
  - 规格
  - 一天几次
  - 一次几片（粒）
  - 血压控制水平
- 如果患者明确未用药，则药物相关槽位为 `not_applicable`，但仍需明确血压控制水平。

### 2. `（若有糖尿病）药物控制方案`

Excel 规则：

- 口服药：药物名称，规格，一天几次，一次几片（粒）
- 胰岛素：胰岛素名称，注射时间，注射单位数
- 血糖控制水平

判定规则：

- 必须先明确是否有口服药、是否有胰岛素。
- 如果触发口服药分支，则以下槽位全部为必填：
  - 药物名称
  - 规格
  - 一天几次
  - 一次几片（粒）
- 如果触发胰岛素分支，则以下槽位全部为必填：
  - 胰岛素名称
  - 注射时间
  - 注射单位数
- 无论触发哪个治疗分支，都必须补齐：
  - 血糖控制水平
- 如果明确既没有口服药，也没有胰岛素，则相应治疗分支标为 `not_applicable`，但仍需继续追问血糖控制水平。

### 3. `（若曾患冠心病）治疗方式`

Excel 规则：

- 治疗方式：手术 / 药物 / 观察
- 手术：手术时间，手术术式
- 药物：药物名称，规格，一天几次，一次几片（粒）
- 治疗效果：是否仍存在冠脉狭窄，症状是否好转，是否有再患冠心病

判定规则：

- 必须先明确治疗方式主类。
- 如果触发手术分支，则以下槽位全部为必填：
  - 手术时间
  - 手术术式
- 如果触发药物分支，则以下槽位全部为必填：
  - 药物名称
  - 规格
  - 一天几次
  - 一次几片（粒）
- 治疗效果部分以下槽位均为必填：
  - 是否仍存在冠脉狭窄
  - 症状是否好转
  - 是否有再患冠心病

### 4. `（若曾患脑血管病）具体疾病、治疗方式及有无后遗症`

Excel 规则：

## 对 `field_rules.py` 的设计要求

本次实现应遵循以下边界：

- 仅修改 `field_rules.py`
- 不要求把 Excel 第四列动态读入运行时
- 但这 5 个字段的规则文本与完成判定，必须严格参照 Excel 第四列手工固化到 `field_rules.py`

`field_rules.py` 需要具备：

- 能识别这 5 个字段属于“严格复杂字段”
- 能基于当前字段值判断哪些槽位已回答、未知或不适用
- 能在仍有缺失槽位时维持 `ask_again`
- 能在所有已触发必填槽位进入终态后转为 `done`
- 不能再让这 5 个字段走 `_is_specific_text()` 的宽松收口

## 非目标

本设计不包含以下内容：

- 不重构全部字段的状态管理
- 不新增新的数据库或持久化结构
- 不改 Excel 解析器去动态读取第四列规则
- 不一次性重做所有开放文本问题的完成逻辑

## 风险与约束

- 当前系统仍是“字段级”而非“槽位级”状态机，因此复杂字段槽位判定必须以当前字段累计文本为依据完成。
- 如果槽位识别规则写得过于宽松，仍可能提前收口。
- 如果槽位识别规则写得过于严格，会导致频繁 `ask_again`。
- 因此实现时应优先保证：
  - 对同一未知槽位不重复死问
  - 不因单个未知槽位跳过全字段其他槽位
  - 仅在已触发必填槽位全部终态化后 `done`

## 通过标准

以下情况应视为设计达标：

- 上述 5 个字段不再因为一句模糊文本就直接 `done`
- 患者明确说“不知道”后，同一槽位不会被持续重复追问
- 同字段其他未完成槽位仍会继续追问
- 药物、手术、疗效等分支按患者实际回答被触发
- 这 5 个字段的完成标准与 Excel 第四列一致
